# 프로젝트 기획서: RFP-RAG

## 1. 프로젝트 개요

### 배경
B2G(Business-to-Government) 입찰 컨설팅 현장에서는 나라장터 등에 하루 수백 건의 RFP(제안요청서)가 올라온다. 한 문서당 수십 페이지에 달하는 내용을 담당자가 일일이 읽고 분류하는 것은 비효율적이다. 이를 해결하기 위해 RFP 문서를 빠르게 검색하고 핵심 정보를 추출할 수 있는 RAG 시스템을 구축한다.

### 목표
- 100개의 실제 RFP 문서를 기반으로 자연어 Q&A가 가능한 RAG 시스템 구축
- 단계적 아키텍처 고도화를 통해 검색 품질과 응답 정확도를 개선
- 비교 실험을 통한 근거 기반 기술 의사결정 수행
- FastAPI + React 기반 웹 서비스로 실제 배포까지 완료

### 프로젝트 성격
- 개인 포트폴리오 프로젝트
- 클라우드 API 기반 (GCP VM 미사용)

## 2. 데이터

### 데이터셋
- **RFP 문서:** 100개 PDF 파일 (`data/` 폴더)
- **메타데이터:** `data/data_list.csv`
  - 공고번호, 사업명, 사업금액, 발주기관
  - 공개일자, 입찰마감일, 사업요약, 파일명

### 데이터 주의사항
- 원본 RFP 문서는 비밀유지계약상 외부 공유 금지
- `data/` 폴더는 `.gitignore` 처리 (GitHub 업로드 불가)

## 3. 핵심 기능

### 사용자 요구사항
| 기능 | 설명 |
|---|---|
| 단일 문서 Q&A | 특정 RFP 문서의 내용을 질문하면 정확하게 답변 |
| 멀티 문서 비교 | 여러 RFP 문서를 비교 분석하여 답변 |
| 메타데이터 검색 | 발주기관, 사업명, 예산 범위 등으로 문서 필터링 |
| 대화 맥락 유지 | 후속 질문 시 이전 대화 맥락 반영 |
| 모름 답변 | 문서에 없는 정보는 없다고 명확히 답변 |

## 4. 단계별 개발 로드맵

### Phase 1: Naive RAG (베이스라인)
**목표:** 기본 파이프라인 구축 및 베이스라인 성능 측정

- PDF 파서 비교 실험 → 최적 파서 선택
  - PyMuPDF vs pdfplumber vs OpenDataLoader
- 청킹 전략 비교 실험
  - Fixed size vs RecursiveCharacterTextSplitter vs Semantic chunking
- 기본 벡터 검색 (Dense only) 구현
- FastAPI 기본 엔드포인트 구축
- 성능 베이스라인 측정

**완료 기준:** 고정 질문 세트 20개에 대한 베이스라인 성능 측정 완료

---

### Phase 2: Hybrid RAG
**목표:** 검색 품질 향상 및 임베딩 모델 비교 실험

- BM25 + Dense Vector 병렬 검색 구현
- RRF(Reciprocal Rank Fusion)로 결과 결합
- Cohere Rerank 적용
- 메타데이터 필터링 (발주기관, 예산, 날짜)
- 임베딩 모델 비교 실험
  - OpenAI text-embedding-3-small vs Cohere embed-multilingual-v3.0
- React 프론트엔드 기본 채팅 UI 구현

**완료 기준:** Phase 1 대비 Recall@K 15% 이상 향상

---

### Phase 3: Corrective RAG
**목표:** 검색 결과 신뢰도 향상 및 할루시네이션 감소

- LLM-as-judge로 검색 결과 관련성 평가
- 낮은 신뢰도 시 쿼리 재작성(Query Rewriting) 후 재검색
- (선택) HyDE: 가설적 답변 생성 후 임베딩 검색
- 대화 히스토리 관리 개선

**완료 기준:** 문서 외 질문 거부율 90% 이상, 응답 정확도 향상

---

### Phase 4: Agentic RAG
**목표:** 복잡한 멀티스텝 쿼리 처리 및 배포

- LangGraph 기반 에이전트 구현
  - 계획 → 검색 → 추론 → 자기 수정 루프
- Supabase(pgvector)로 Vector DB 마이그레이션
- Docker 컨테이너화 (FastAPI, React)
- AWS 배포 (ECR + EC2/ECS, S3+CloudFront)

**완료 기준:** 멀티 문서 비교 질문 처리, 실제 서비스 배포 완료

## 5. 성능 평가 전략

### 평가 질문 세트 (20개 고정)
- **단일 문서 Q&A** (5개): 특정 기관 RFP의 요구사항 추출
- **멀티 문서 비교** (5개): 두 기관 시스템 비교
- **후속 질문** (5개): 이전 답변 기반 follow-up
- **문서 외 질문** (5개): 문서에 없는 내용 (거부해야 함)

### 평가 지표
| 지표 | 설명 |
|---|---|
| Recall@K | 상위 K개 청크 내 정답 포함율 |
| MRR | 정답 청크의 평균 순위 |
| LLM-as-judge | GPT-4o가 답변 품질 1~5점 평가 |
| 응답 속도 | 평균 응답 시간 (초) |
| 거부율 | 문서 외 질문에 대한 올바른 거부 비율 |

### 비교 방식
- 동일 질문 세트로 Phase 완료마다 측정
- 결과를 표로 정리하여 ADR 문서에 기록
